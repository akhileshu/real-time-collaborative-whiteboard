## Constraints and sequencing decisions

- The first slice is workspace bootstrap, so every later slice runs through the
  same Bun commands and package boundaries.
- Canvas rendering and interaction use a stable scene-model interface. The
  renderer does not know whether data came from local state, WebSocket, or Yjs.
- High-frequency pointer and cursor state stays outside ordinary React render
  state where possible.
- Incoming WebSocket data is untrusted: validate it at the transport boundary
  with shared Zod contracts.
- Redis is deferred until there is a demonstrated multi-process requirement.
- Yjs is deferred until the local document operations and update contract are
  tested; it must not be introduced only as a dependency without a convergence
  invariant.
- Authentication and document permissions are not acceptance criteria in the
  current specification. If required, add them before persistence is exposed.

## Detailed slice documents

When implementation begins, create one document per slice under `docs/slices/`.
Each document must contain: `Goal`, `Non-goals`, `Design`, `Interfaces`,
`Execution flow`, `Failure cases`, `Tests`, `Definition of done`, and `Future
improvements`.
