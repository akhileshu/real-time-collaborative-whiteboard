# Dependency management and engineering trade-offs

Add a row here whenever a significant package or runtime dependency is
introduced. Keep the reason, rejected alternatives, and lifecycle decision
visible so dependencies do not become accidental architecture.

| Package / runtime | What problem it solves | What if we do not use it? | Considerable alternatives | Current decision |
|---|---|---|---|---|
| **Bun** | Workspace tooling and the standalone realtime runtime | Use separate package managers or Node tooling; slower and less consistent local commands | npm/pnpm workspaces, Node.js | Use for workspace scripts and `apps/realtime` |
| **Next.js** | Web application routing, rendering, and production build | Build routing, bundling, and SSR infrastructure ourselves | Remix, Vite + React Router | Use the template baseline with the App Router |
| **React** | Component rendering and low-frequency UI state | Use a different UI runtime or build DOM updates manually | Vue, Svelte | Use for web UI; keep high-frequency canvas state outside React renders |
| **Zod** | Runtime validation for shared HTTP/WebSocket boundaries | Trust unvalidated external payloads or maintain duplicate validators | Valibot, ArkType, hand-written guards | Use in `packages/contracts` and at transport boundaries |
| **@whiteboard/contracts** | Shared schemas and transport types between web and realtime apps | Duplicate message definitions and allow client/server drift | Generated OpenAPI/JSON Schema, duplicated local types | Keep as a small source package; add only stable cross-process contracts |
| **next-themes** | Theme preference handling in the adapted web shell | Reimplement theme persistence and hydration handling | CSS-only theme, custom localStorage adapter | Retain from the template while the shell uses it |
| **Vitest** | Fast unit tests for pure helpers, schemas, and deterministic boundaries | Use framework-specific tests or Bun's runner and lose the configured test interface | Bun test, Jest | Use for unit tests through `bun run test:unit` |
| **Playwright** | Browser-visible verification of high-value user workflows | Rely on manual browser checks and miss regressions in navigation/rendering | Cypress, WebdriverIO | Use for E2E tests through `bun run test:e2e`; install browsers in CI/development setup |
| **Yjs** | Standard CRDT structures for safe concurrent canvas updates | Design and test conflict resolution from scratch | Automerge, Liveblocks, custom OT | Introduce in Slice 6 behind a room/document adapter; use only after convergence tests exist |
| **Redis** | Cross-process presence fan-out and buffered persistence coordination | In-memory rooms work only on one process; horizontal scaling needs a replacement | NATS, RabbitMQ, single-node memory | Defer until multi-process scaling is demonstrated |
| **Prisma** | Generated PostgreSQL client used by ZenStack for durable data | Write and maintain raw SQL/data mapping code | Drizzle, Kysely, `pg` | Use only behind the ZenStack-enhanced tRPC context |
| **ZenStack** | Authoritative ZModel schema, policies, enhanced Prisma client, and generated CRUD routers | Hand-write CRUD validation, authorization, and repetitive tRPC procedures | Direct Prisma, Drizzle + custom policy layer | Use ZenStack 2.x with the Prisma and tRPC plugins |
| **tRPC** | Typed procedure transport between the App Router client and server | Duplicate request/response types across API boundaries | REST, GraphQL, server actions | Use tRPC v10 through one App Router route handler |
| **TanStack React Query** | Server-state cache, loading/error lifecycle, and mutation invalidation | Manually coordinate fetch state and cache updates | SWR, Redux Toolkit Query | Use through the tRPC React client |
| **React Hook Form + `@hookform/resolvers`** | Reduces repetitive form state, submit, reset, and field-error plumbing while connecting forms to Zod schemas | Hand-write controlled field state, submit prevention, and error mapping for every form | Formik, native uncontrolled forms with custom validation | Use for web forms with `zodResolver`; keep existing Zod schemas authoritative |
| **Zustand** | Small client-only UI state such as Todo filters and future workspace controls | Lift every UI flag through React props or duplicate it in server state | React context, Redux, Jotai | Use small typed stores only; never store canonical server records |
| **Docker Compose** | Reproducible local PostgreSQL runtime for development and E2E verification | Require each developer to provision PostgreSQL manually | Local PostgreSQL, Testcontainers | Use a project-level PostgreSQL service |
| **Elysia** | Typed WebSocket route lifecycle, payload limits, and Bun-compatible upgrade handling for room transport | Maintain route lifecycle and protocol wiring directly in `Bun.serve` | Fastify, Hono, native Bun server | Use Elysia 1.x in `apps/realtime`; keep the room registry transport-independent and do not use the archived `@elysiajs/websocket` plugin |

## Dependency rules

- Prefer a platform primitive when it is sufficient for the current slice.
- Add a package only when it removes meaningful implementation risk or creates
  a stable boundary.
- Remove template dependencies that are not used by the current slice.
- `schema.zmodel` is authoritative; generated Prisma and tRPC files must not be hand-edited.
- Do not introduce feature-specific API routes or server actions when a tRPC procedure is the application boundary.
- Update this table in the same change that adds a significant dependency.
